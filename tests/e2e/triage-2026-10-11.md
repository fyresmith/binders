## Category 3: real bugs or open findings (tests left failing, not fixed)

1. **Bring back on a note that holds only CRLF properties writes nothing** (specs-qa11-note-snapshots.mjs, "a note of only its properties..."). It can lose a writer's work, so it comes first.
   - Steps:
     1. Make a note whose whole file is `---\r\nstatus: draft\r\nsynopsis: ...\r\n---\r\n` (properties only, CRLF).
     2. Seed a snapshot with text.
     3. Show snapshots, pick it, press Bring back.
   - Expected: the properties stay as written (CRLF) and the snapshot's text follows them.
   - Actual: the file stays properties-only. The same case with LF properties works, and the notice said "Brought back the snapshot".
   - I did not locate the code; look in the bring-back path in src/snapshots.ts.
   - A separate finding from the same test: Obsidian itself rewrites a CRLF note as LF when its tab is closed. This happens with Binders disabled, so it is not the plugin. I put the CRLF back in the test before the bring-back step.
2. **A name of 120 accented letters gives a raw "ENAMETOOLONG: name too long, open ..." error in the Rewrite dialog** (specs-qa11-note-snapshots.mjs).
   - Cause: `validName` in src/snapshot-text.ts:47 counts characters, not bytes. The file system limit is 255 bytes, and the timestamp prefix plus ".snapshot" use part of it.
   - Fix: also refuse names whose UTF-8 bytes go over about 200, with the same plain wording as "That name is too long".
   - Nothing is written, so no text is lost.
3. **Bring back overwrites a note made since in a re-created folder** (specs-qa11-bringback.mjs, "notes deleted since, a folder deleted...").
   - Steps:
     1. Snapshot a folder with `Doomed/Inside one.md` (three lines).
     2. Delete `Doomed`, re-create it, and write a different three-line `Doomed/Inside one.md`.
     3. Bring back "Everything".
   - Expected (docs/snapshots.md, "A name that a new note has now stays that note's"): the snapshot's note comes back as "Inside one 2".
   - Actual: the new note's text is replaced by the snapshot's. It survives only in the "Before bringing back" snapshot. At the root the same case works: "Lone 2" was made and the new Lone stayed.
   - Suspect: src/binder-snapshot-text.ts:348-349, "what is left at the same path is the same note, written again from nothing". The loop joins any leftover at the same path regardless of text.
   - I changed the test's fixtures to notes of three or more lines. The documented rule says a snapshot note under three lines at a path is taken for that note whatever it says, and every snapshot note in the fixture was shorter than that. The remaining assertion ("the other note made since stays") is the bug.
4. **Design question, not a bug (bringback "a folder moved out of the binder", links on and off).**
   - Bring back writes only inside the folder. Notes that left the binder are made again and the moved ones stay in Elsewhere, so there are duplicates.
   - I repaired the test to assert exactly that, plus that the Elsewhere notes are untouched, byte for byte. The maintainer may prefer a different design.
5. **Nits in specs-qa11-outliner.mjs, tests left failing:**
   - "End, Home and Page Down": after End then Home, scrollTop is 39, not 0. The sticky header puts row 1 under it and 39 px of the block above the header stays scrolled away. Cause: `scrollIntoView({block:'nearest'})` at the row calls in src/view/outliner.ts (lines 470, 993, 1010, 1075). Fix: scroll to 0 when the first row is focused.
   - "A column's width is kept when it is hidden and shown again": Hide column removes the column's spec with its width (src/view/outliner-columns.ts:125), so showing it again gives 80 px, not 170. Fix: keep the width in a separate map.
